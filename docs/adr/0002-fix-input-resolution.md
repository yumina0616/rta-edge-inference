# ADR-0002: 입력 해상도를 416×416으로 고정한다

## Status

Accepted — 2026-08-05

## Context

[ADR-0001](0001-select-yolov8n-model.md)에서 YOLOv8n을 선정했다. YOLOv8n은 임의의 고정
해상도로 export할 수 있으며, 입력 해상도는 추론 latency와 정확도에 직접적인 영향을 준다.

이후 M3(FP32 vs INT8 비교), M4(벤치마크 자동화)에서 "동일 조건 비교"가 성립하려면 해상도가
Phase 1(이 프로젝트의 1단계 필수 목표 범위, [ADR-0001](0001-select-yolov8n-model.md) 참고) 전 구간에서 하나의 값으로 고정되어야 한다.

검토한 대안:

- **640×640**: YOLOv8 COCO 사전학습 가중치의 기본 해상도. 정확도 우선이지만 연산량이 가장 큼.
- **416×416**: 정확도-속도 절충점. 640×640 대비 연산량이 약 42% 수준으로 감소.
- **320×320**: 속도 최우선. 자원 제약에는 가장 유리하지만 작은 객체 탐지 정확도 손실이
  눈에 띄게 커질 수 있음.

## Decision

Phase 1 전 구간(M2~M4)의 입력 해상도를 **416×416**으로 고정한다.

## Consequences

긍정적인 영향:

- 640×640 대비 연산량이 크게 줄어 자원 제약 환경이라는 프로젝트 목표에 부합한다.
- 320×320 대비 작은 객체 탐지 정확도 손실이 적다.

부정적인 영향:

- 640×640을 사용할 때보다 정확도(mAP)가 낮게 나올 가능성이 있다.
- 이후 해상도를 바꾸려면 M2~M4에서 이미 만든 벤치마크 결과를 전부 재수집해야 한다 — 되돌리기 비용이 큰 결정이므로 이후 함부로 변경하지 않는다.

후속 작업:

- ONNX export 시 `dynamic=False`로 고정 shape을 강제한다.
